# Commit-Reveal Cloud Auction Demo

Local Hardhat demo for a cloud-resource auction that resists bid front-running.

`VM-001` is represented on-chain as **4 CPU, 16 GB RAM, 100 GB storage, for 2 hours**. This is an allocation record only: the demo does not provision a real VM or custody ETH.

## Security property demonstrated

1. Bidders commit `keccak256(abi.encodePacked(bid, nonce))`, never their bid, while the commit window is open.
2. A reveal is stored only if its bid and nonce reproduce that commitment.
3. `revealBid` deliberately does not calculate `highestBid` or `winner`.
4. Only after the reveal deadline can `finalizeAuction` determine the highest valid bid and allocate the resource.

The companion `OpenBidBaseline` makes the contrast explicit: its visible 5 ETH-equivalent bid can be immediately beaten by an attacker submitting 6.

## Run locally

```powershell
npm install
npm test
npm run demo
```

`npm run demo` runs the complete deterministic demonstration on Hardhat's in-process local network. Its expected secure-auction result is Bidder B winning at 8 ETH-equivalent price units, with `VM-001` allocated to that address.

For an interactive multi-terminal run:

```powershell
npm run node
npm run deploy
```

Use the printed address with the scripts below. Prices are specified in wei. `commit.js` generates a fresh cryptographically random 32-byte nonce with `ethers.randomBytes(32)`, then stores the matching bid/nonce secret in `data/bid-secrets.json` (which is ignored by Git). Do not share or lose that file before revealing. The final argument selects the local Hardhat account: `1`, `2`, and `3` are the three demo bidders; account `0` is the auctioneer.

```powershell
npx hardhat run scripts/commit.js --network localhost -- <auction-address> 5000000000000000000 1
npx hardhat run scripts/commit.js --network localhost -- <auction-address> 8000000000000000000 2
npx hardhat run scripts/commit.js --network localhost -- <auction-address> 6000000000000000000 3

# After the 60-second commit window expires
npx hardhat run scripts/startReveal.js --network localhost -- <auction-address>

npx hardhat run scripts/reveal.js --network localhost -- <auction-address> 1
npx hardhat run scripts/reveal.js --network localhost -- <auction-address> 2
npx hardhat run scripts/reveal.js --network localhost -- <auction-address> 3

# After the 60-second reveal window expires
npx hardhat run scripts/finalize.js --network localhost -- <auction-address>
```

The auctioneer must call `startReveal()` after the commit deadline. The browser classroom interface supports public read-only views, wallet bids, secret recovery, organizer phase controls, activity, and QR invites.

## Classroom web app

Run the complete local demo stack with one command:

```powershell
npm run classroom
```

This compiles the contract, starts a local Hardhat chain, deploys a five-minute commit/five-minute reveal auction, and serves the UI at `http://localhost:4173`. Open the invite URL printed by the deploy script; on a trusted classroom LAN, use the printed LAN preview. The local chain uses temporary, publicly known demo accounts and has no real value; do not expose it outside a trusted classroom network. The QR invite URL contains the public address and network only. The QR bitmap is generated by `api.qrserver.com`, which receives this public invite URL; bid secrets are never sent to it.

To serve the UI separately, use `npm run app`. The auction address can be added with the locator button beside the resource name. Invite links open directly to the selected network and auction. Each bidder needs a compatible wallet that injects an EIP-1193 provider. On phones, participants may need to open the invite inside their wallet's built-in browser; WalletConnect is not integrated. During a commit, the browser generates the random nonce, saves a local recovery secret before opening the wallet, and provides a JSON download. Keep that file private and restore it in the same browser or wallet before reveal. The contract allows one commitment per wallet and enforces the configured bid ceiling; this is not a one-student identity check.

### Sepolia classroom deployment

1. Copy `.env.example` to `.env` and set `SEPOLIA_RPC_URL`, `DEPLOYER_PRIVATE_KEY` for a test-only deployer, and the desired limits. `.env` is git-ignored and loaded by Hardhat.
2. Compile and deploy with `npm run compile` and `npm run deploy:sepolia`. The script records the public contract address in `web/deployments.json` and prints an invite URL.
3. Host the `web/` folder on an HTTPS static host. Ensure the generated `deployments.json` is included, or open the site with `?network=sepolia&address=<contract-address>`.
4. Share the generated QR code. Participants connect a wallet on Sepolia and use test ETH for transaction gas. The contract accepts no bid funds.

Ethereum testnet transactions require public RPC availability and test ETH. Do not put an RPC provider secret in `web/` or publish a wallet private key. A QR code cannot prevent one person from using multiple wallets; use an instructor-managed enrollment process if that control is required.

## Deploy the classroom UI on Render

The repository includes a Render Blueprint in `render.yaml`. In Render, create a new Blueprint from `Arnav2580/commit-reveal-cloud-auction` and select the `main` branch. Render builds the contract ABI and publishes the static browser app from `web/` at a public `onrender.com` URL. The Blueprint enables automatic deploys when `main` changes.

This hosts the user interface only. The committed `web/deployments.json` contains the local Hardhat demo address, which is not available on Render or to classroom participants. To run a shared public auction, deploy a fresh contract to Sepolia with a testnet-only deployer key, then publish the resulting **contract address** in `web/deployments.json` and redeploy. Keep `SEPOLIA_RPC_URL` secrets and `DEPLOYER_PRIVATE_KEY` out of the repository and static-site environment. Participants still need wallets with Sepolia test ETH for gas; bids and recovery secrets remain in each bidder's browser.

## Research paper and measured figures

The formatted PDF research paper, including a market comparison graph, limitations, six analytical figures, and a complete screenshot from the local demo, is [paper/research-paper.pdf](paper/research-paper.pdf). The editable source remains in [paper/research-paper.md](paper/research-paper.md). Regenerate benchmark data and paper visuals with:

```powershell
npm run benchmark
```

Then rebuild the figures and PDF:

```powershell
python paper/generate_figures.py
python paper/generate_market_chart.py
python paper/photos/make_screenshot.py
python paper/photos/make_contact_sheet.py
python paper/build_pdf.py
```

The benchmark runs on Hardhat's local EVM; it does not measure public testnet latency or classroom capacity. Sepolia deployment requires SEPOLIA_RPC_URL, DEPLOYER_PRIVATE_KEY, and optionally MAX_BID in the environment. The current contract records allocation only; it does not receive funds or provision cloud resources.
